Good—this is the exact place where SQL becomes more powerful than application logic.
Based on your schema (categories + project_categories), the typical way to compute “category + number of projects” is:

SELECT 
    c.category_id,
    c.name,
    COUNT(pc.project_id) AS project_count
FROM categories c
LEFT JOIN project_categories pc
    ON c.category_id = pc.category_id
GROUP BY c.category_id, c.name
ORDER BY c.name;

What this is doing (mapped to your design):
categories c = base table (one row per category)
project_categories pc = relationship table
LEFT JOIN ensures categories with 0 projects still appear
COUNT(pc.project_id) = number of linked projects per category
GROUP BY collapses multiple joined rows into one per category
Why this matters in your architecture:

This query pushes work into the database layer, meaning:

Node.js receives already-aggregated results
No manual grouping logic needed in JavaScript
EJS stays purely for display (<%= category.name %> (<%= category.project_count %>))
