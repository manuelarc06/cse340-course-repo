In most web apps, this is where we handle creating new users and securely storing passwords (never storing raw passwords). Typically we use something like bcrypt to hash passwords before saving them to the database.

import { db } from "./db.js";

  const { email, password } = req.body;

  // 1. Check if user already exists

    where: { email }

    data: {
      email,
      password: hashedPassword
    }
  });

  return res.status(201).json({ message: "User created", userId: newUser.id });
}

Now we’ll move to **Topic 2: Login and Sessions**.
In most web apps, login does two key things:
1. Verifies the password against the stored hash
2. Creates a session (or issues a token) so the user stays authenticated

Here’s a typical session-based login example (Express-style):

```javascript
import bcrypt from "bcryptjs";
import { db } from "./db.js";

export async function loginUser(req, res) {
  const { email, password } = req.body;

  // 1. Find user
  const user = await db.user.findUnique({
    where: { email }
  });

  if (!user) {
    return res.status(400).json({ message: "Invalid credentials" });
  }

  // 2. Compare password
  const isValid = await bcrypt.compare(password, user.password);

  if (!isValid) {
    return res.status(400).json({ message: "Invalid credentials" });
  }

  // 3. Create session
  req.session.user = {
    id: user.id,
    email: user.email,
    role: user.role
  };

  return res.status(200).json({ message: "Logged in successfully" });
}
```

This is where authentication becomes “stateful” via sessions.

But I want to zoom in on something important: you mentioned *sessions in requireLogin*, which means the session still has to be created somewhere during login. That connection is what often makes or breaks auth systems.
Here’s a typical **middleware setup** for what you described (Topic 3):

```javascript id="mw1a92"
export function requireLogin(req, res, next) {
  if (!req.session || !req.session.user) {
    return res.status(401).json({ message: "You must be logged in" });
  }
  next();
}

export function requireRole(role) {
  return (req, res, next) => {
    if (!req.session?.user) {
      return res.status(401).json({ message: "You must be logged in" });
    }

    if (req.session.user.role !== role) {
      return res.status(403).json({ message: "Forbidden: insufficient permissions" });
    }

    next();
  };
}
```

This pattern is powerful because it separates concerns:
* login happens once
* session stores identity
* middleware enforces rules everywhere consistently
